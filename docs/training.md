# EfficientNet-B0 training

Actual training requires a cleared dataset source, a successful dataset preparation run, and `data/processed/manifest.csv`. The active Kaggle candidate is still blocked by missing credentials, missing image files, and unclear license status. No model has been trained and no performance metrics currently exist.

## Architecture

The initial classifier uses torchvision EfficientNet-B0 with ImageNet weights. Its final linear layer is replaced at runtime using the deterministic class list present in the prepared manifest; no class count is hardcoded. The training checkpoint is designed for the backend's one-time lazy model loader.

## Dataset input and indexing

`training/dataset.py` reads only these manifest fields:

- `image_path`
- `target_label`
- `split`

Class order follows `data/dataset_config.json`, filtered to labels actually present in the manifest. Any unexpected manifest labels are appended alphabetically. The exact list is stored inside the checkpoint and written to `backend/models/class_names.json` only after a real best checkpoint is saved.

## Preprocessing and augmentation

Training uses resize, a constrained random resized crop (85–100% scale), horizontal flip, rotation up to 10 degrees, mild brightness/contrast/saturation/hue jitter, tensor conversion, and ImageNet normalization.

Validation, test, and inference use deterministic resize to 256-equivalent, center crop to 224, tensor conversion, and ImageNet normalization. These match the official EfficientNet-B0 weight normalization. Augmentations are deliberately mild to limit distortion of clinically meaningful structures.

## Transfer learning

Training has two stages:

1. The EfficientNet feature backbone is frozen for five epochs while the replacement classifier learns at `1e-3`.
2. The deepest three feature blocks are unfrozen and fine-tuned at `1e-4`, while the classifier retains its separate learning rate.

Both boundaries are configurable in `training/config.py`. Training the entire backbone immediately is avoided.

## Optimization and imbalance

- Loss: cross-entropy
- Optimizer: AdamW with weight decay `1e-4`
- Scheduler: `ReduceLROnPlateau`, because validation loss is the monitored generalization signal and the useful decay point is not known in advance
- Early stopping: validation loss, patience 7
- Optional inverse-frequency class weights: disabled by default; enable only after reviewing actual prepared distributions

## Reproducibility and devices

Python, NumPy, PyTorch, and CUDA seeds are set to 42. cuDNN deterministic mode is enabled and benchmarking is disabled. This improves reproducibility but can reduce GPU throughput; some GPU operations can still vary across hardware/library versions.

CUDA is selected automatically when `torch.cuda.is_available()` is true, otherwise CPU is used. `NUM_WORKERS=0` is the safe Windows default. Reduce `BATCH_SIZE` in `training/config.py` if GPU memory is insufficient.

## Installation

Create a dedicated virtual environment. The requirements pin the official PyTorch 2.7.0 / torchvision 0.22.0 pair. For NVIDIA CUDA, use the platform-specific command generated by the [official PyTorch installer](https://pytorch.org/get-started/locally/) instead of blindly installing a CPU wheel.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r training\requirements.txt
```

## Workflow

```powershell
python scripts\prepare_dataset.py
python scripts\inspect_dataset.py
python training\train.py
python training\evaluate.py
```

When the manifest is missing, training prints an acquisition/preparation message, exits with code 2, and creates no files.

## Outputs created only by real execution

Training creates the following only after at least one real validation epoch:

- `backend/models/best_model.pth`
- `backend/models/class_names.json`
- `reports/training_history.json`
- `reports/training_history.png`

The checkpoint contains model state, exact class names, model name, image size, serialized configuration, best validation accuracy/loss, and epoch.

Evaluation loads the best checkpoint and uses only the held-out `test` split. It then creates:

- `reports/test_metrics.json`
- `reports/classification_report.txt`
- `reports/confusion_matrix.png`

Metrics include accuracy, macro/weighted F1, and per-class precision, recall, F1, and support. No output should be interpreted as proof of medical validity.

## Inference and backend loading

`training/inference.py` loads the shared EfficientNet architecture and produces a softmax-ranked top three with a research-use disclaimer. The backend checks `backend/models/best_model.pth` once when its inference module initializes:

- absent checkpoint: API remains healthy and reports `model_loaded: false`;
- valid checkpoint: model loads once and health reports model name and class count;
- invalid checkpoint: the error is logged and the API remains available without claiming a loaded model.

The backend never reloads weights for each request.
